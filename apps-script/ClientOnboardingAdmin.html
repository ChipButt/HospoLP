Step 4 — Create each client's website hosting (£0)

For each approved client, first create a private GitHub repository, then connect Cloudflare Pages separately. If a repository already exists, only the Cloudflare connection is needed. These steps do not activate a customer domain or replace their finished website.

Checking hosting connection…

One-time setup: The owner must configure three secret Script Properties in the existing Google Apps Script project: CHIPIN_GITHUB_PROVISION_TOKEN, CHIPIN_CLOUDFLARE_API_TOKEN and CHIPIN_CLOUDFLARE_ACCOUNT_ID. Never share tokens in client briefs, screenshots or GitHub source. Cloudflare must also be authorised to access newly created private repositories through its GitHub integration.

Important: Provisioning does not alter DNS, attach a customer domain, purchase a domain, or publish approved content. Connect the customer's domain only after final written approval and verify their email/MX records beforehand.

Step 5 — First draft review & final approval

When the first draft is ready in Cloudflare Pages, prepare the review link and email it. The client's three-day feedback window begins when the first invitation email is sent, not when you prepare the link. Clients can browse the website, pin comments to a page, then submit one consolidated list. You track amendments here, mark them complete and request their final written sign-off. The live domain remains disconnected until approval.

Do not send clients a private GitHub repository link. Send the client-specific review portal URL. Note: an unprotected pages.dev preview is publicly accessible even though the review link requires a token. Use Cloudflare Access or avoid placing confidential assets on staging.
